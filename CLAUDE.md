# AdaptMap (Project_Focal): project briefing

SIH 2026 problem SIH26053, "Adaptive Variable Resolution 2.5D LiDAR Mapping for Dynamic Environment
Perception", by team LORENZINI. Also used as a patent proof of the method.
**Current status, checklist and next steps: [docs/STATUS.md](docs/STATUS.md). Read it first.**

## What it does
3D LiDAR scan → GPU preprocessing → MinkUNet sparse-CNN semantic segmentation → a **foveated
2.5D semantic elevation map** → terrain analysis → Nav2 costmap → autonomous navigation.

- **Foveated map:** nested square zones at 5 cm (0–10 m), 10 cm (10–30 m), 25 cm (30–50 m) and
  50 cm (50–100 m). That's 702,400 cells instead of 16 M for a uniform 5 cm grid.
- **Speed-adaptive:** the 5 cm zone grows with reaction + braking distance.
- **Per cell:** height statistics, fused class probabilities, a ground surface and the clearance
  under overhangs.
- **Dynamic scenes:** ray clearing plus class-aware decay.

The method is described in `docs/METHOD.md`; the numbers are in `docs/RESULTS.md`.

## Layout
- `adaptmap/`: core library, no ROS dependency.
  - `foveated_map.py`: the map (fusion, ray clearing, views, `set_zones`).
  - `preprocess.py`, `segmentation.py`, `terrain.py`, `adaptive.py`, `classes.py`, `config.py`.
  - `tests/`: 20 pytest tests; CPU-safe, also run by GitHub Actions.
- `configs/adaptmap.yaml`: every tunable value (zones, fusion, ray clearing, terrain limits,
  adaptive zones, model).
- `ros2_ws/src/`:
  - `adaptmap_sim`: Gazebo worlds and the rover; `world:=` launch argument.
  - `adaptmap_ros`: the mapping node, launch files, RViz config, `test/` launch_testing smoke test.
  - `adaptmap_nav`: Nav2 parameters and launch.
- `tools/`: everything else:
  - benchmarks;
  - world generation (`make_world.py --seed N`);
  - auto-labelled data (`gen_training_data.sh`, `record_labeled.py`, `autolabel.py`, `fix_labels.py`);
  - `finetune.py`;
  - evaluations (`eval_bag.py`, `eval_semanticposs.py`, `run_dataset.py`);
  - viewers and videos (`view25d.py`, `render_live.py`, `resolution_figure.py`);
  - demo scripts (`manual_test.sh`, `capture_demo.sh`, `stop_demo.sh`);
  - `nav_scenarios.py`, `make_results.py`.
- `docs/`: METHOD (technical disclosure), RESULTS (generated by `tools/make_results.py` from
  `docs/*.json`), TESTING (plain-language guide), STATUS, figures.
- **Not in git:**
  - `.venv/` (6.9 GB);
  - `data/` (~17 GB: sim training data, real datasets, recordings);
  - `checkpoints/*.pth`. The pretrained model comes from `scripts/download_checkpoint.sh`; the
    fine-tuned ones are local only.

## Environment
- Ubuntu 22.04, RTX 4050 6 GB, ROS 2 Humble, Gazebo Harmonic, Python 3.10 venv at `.venv`.
- Torch 2.1 / cu121, mmdet3d 1.4, spconv. **numpy must stay < 2.**
- Run Python as `.venv/bin/python`. Anything that imports `rclpy` (the node, `view25d.py`,
  `run_dataset.py`, evaluation tools) needs `source /opt/ros/humble/setup.bash` first, and
  usually `source ros2_ws/install/setup.bash` too.
- After adding launch files or packages: `cd ros2_ws && colcon build --symlink-install`.
- **No passwordless sudo.** System installs go in a script under `scripts/` that the user runs.
- **Nav2 is not installed yet.** The user needs to run `sudo bash scripts/install_nav2.sh`.

    intensity;
  - the sim model expects constant intensity 0.25.

## Gotchas (learned the hard way)
- **Stopping the sim:** stop anything you launched with `bash tools/stop_demo.sh`. Don't run
  `pkill -f <pattern>` from a shell whose own command line contains that pattern: it kills
  itself (exit 144).
- **Don't launch and stop in parallel tool calls.** They race.
- **One GPU job at a time.** Training, the sim and evaluations all share 6 GB.
- **Screenshots:** GNOME Wayland blocks screenshots (`x11grab` gives black, DBus is denied).
  Render images and videos from ROS topics instead (`render_live.py`, `view25d.py --video`,
  Open3D offscreen works). `view25d.py --selftest file.png` renders the interactive scene.
- **Odometry:** Gazebo odometry reports the model origin (ground level) in world coordinates, and
  the LiDAR is 1.73 m above it. Don't use the Python TF listener for poses: it lags about 2 s
  under GPU load. The node keeps its own odometry history.
- **Message building:** build ROS message arrays with `array.array` / `bytes`. Python lists are
  100× slower and starve other threads.
- **Auto-labels:** object boxes reach down to the ground. The ground-contact rule in
  `autolabel.py` (and `fix_labels.py` for older data) is essential; without it, about 60 % of
  vehicle and pedestrian labels were really ground.
